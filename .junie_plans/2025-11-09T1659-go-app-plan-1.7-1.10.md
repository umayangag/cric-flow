### 1.7 Integration tests — audit & fixes (Parent: 1 → 1.7)
- Inspect `export_fielding_integration_test.go` for:
  - DB connect guard: keep `t.Skip` if `db.Connect` fails.
  - Migrations path: ensure relative path `../migrations` resolves from `go-app/integration` when tests are invoked via `go test ./...` from repo root.
  - Fixture path: `../../tests/fixtures/cricsheet` — verify presence and readability.
  - Exporter invocation: `go run ./cmd/export-dataset --unified --out <tmp>` with `GO_APP_OUTPUT_DIR` in env; add timeout wrapper.
- Create a small helper in `integration/helpers_test.go`:
  - `runWithTimeout(cmd *exec.Cmd, d time.Duration) error` — already present or add if missing.
  - `requireFile(path string) error` for clearer failure messages.
- If any other packages contain tests that perform I/O across packages or depend on DB/external processes, move them to `go-app/integration/` and rename appropriately. Keep unit packages focused on pure logic with mocks.

Acceptance for 1.7:
- All integration tests pass locally on a machine with Postgres, and gracefully skip if DB is not available.
- No flaky sleeps; deterministic assertions using small fixtures. No external network calls.

Verification for 1.7:

- `go test ./go-app/...` from repo root shows integration passing or skipped.
