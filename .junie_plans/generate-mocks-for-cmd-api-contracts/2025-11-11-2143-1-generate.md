# Plan 1: Generate mocks for cmd/api/contracts.go using mockery v3

Parent: none

## Goal
Generate mocks (mockery v3) for interfaces defined in `go-app/cmd/api/contracts.go`, ensuring they are versioned in-repo and easy to use in tests.

## Context
- We have switched to installing Mockery via Homebrew (`brew install mockery`).
- Project has a `.mockery.yml` configured to include `cmd/api` package with `all: true`, which should pick up all interfaces in that directory (including `Client` in `contracts.go`).
- The config currently outputs test-scoped mocks into the same source directories as `mocks_test.go` with package name set to the source package (here: `main`).

## Scope
- Verify `.mockery.yml` settings cover `cmd/api`.
- Run generation with mockery v3.
- Commit generated mocks.
- No runtime code changes.

Out of scope:
- Changing interface names or locations.
- Refactoring `.mockery.yml` beyond what’s necessary for this task.

## Files
- Input: `go-app/cmd/api/contracts.go`
- Config: `go-app/.mockery.yml`
- Output (generated): `go-app/cmd/api/mocks_test.go` (package `main`) — exact path/name per config

## Steps

1. Pre-checks
   - Ensure mockery v3 is installed and on PATH.
   - Confirm `.mockery.yml` includes `cmd/api` with `all: true`.

2. Generate mocks
   - Run `make -C go-app mocks` (calls `mockery --config .mockery.yaml`).
   - This should create/update `go-app/cmd/api/mocks_test.go` containing `MockClient` for interface `Client`.

3. Verify generation
   - Inspect that `MockClient` exists in the generated file with methods:
     - `PredictBatting(ctx context.Context, feats []contracts.BattingFeatures) ([]contracts.BattingPrediction, error)`
     - `PredictBowling(ctx context.Context, feats []contracts.BowlingFeatures) ([]contracts.BowlingPrediction, error)`
   - Build the module to ensure generated code compiles.

4. Commit and PR
   - Create a feature branch and commit generated mocks with a Conventional Commit message.
   - Open a small PR referencing this plan.

## Acceptance Criteria
- A mock for `Client` is generated at `go-app/cmd/api/mocks_test.go` as `MockClient` (in package `main`).
- Running `make -C go-app mocks` regenerates mocks without errors on mockery v3.
- `cd go-app && go build ./...` succeeds.
- README/Makefile already aligned with Homebrew install flow; no changes required.

## Exact Commands

Branching (never commit to main):
- git checkout -b feat/generate-mocks-cmd-api-contracts

Install/verify tool:
- brew install mockery
- which mockery && mockery --version

Generate mocks:
- make -C go-app mocks

Verify compile:
- cd go-app && go build ./...

Optional: view the generated file:
- sed -n '1,120p' go-app/cmd/api/mocks_test.go

## Risks & Mitigation
- Risk: mockery v3 output differences. Mitigation: we’re using config values compatible with v2/v3; verify compile and adjust config only if needed.
- Risk: package `main` mocks are less reusable across packages. Mitigation: acceptable for handler tests; future refactors can relocate interfaces to internal package if broader reuse is needed.

## PR Strategy
- Conventional Commit: `chore(mocks): generate mock for cmd/api/contracts.Client with mockery v3`
- Small PR containing only generated file changes.
