Counting rule
- Count only logical code lines.
- Exclude:
  - Import blocks (single-line `import` and multi-line `import (...)`).
  - Comment-only lines (`//`, `/* ... */` on their own line).
  - Blank lines.

Acceptance criteria
- Each `go-app/cmd/*/main.go` counts ≤ 30 LOC per the rule above.
- A verification command prints a summary with PASS/FAIL per file and a non-zero exit if any exceed the limit.

Verification commands
- From repo root (or cd go-app), run:
```
cd go-app
# Script: count logical LOC for each cmd/*/main.go
FAIL=0
while IFS= read -r -d '' f; do 
  cnt=$(awk '
    BEGIN{inimp=0}
    /^import \(/ {inimp=1; next}
    inimp==1 && /^\)/ {inimp=0; next}
    inimp==1 {next}
    /^\s*import\s+\"/ {next}           # single-line import
    /^\s*\/\// {next}                  # line comment
    /^\s*$/ {next}                       # blank
    {c++}
    END{print c+0}
  ' "$f")
  status="PASS"; [ "$cnt" -le 30 ] || { status="FAIL"; FAIL=1; }
  printf "%3d  %s  %s\n" "$cnt" "$status" "$f"
done < <(find cmd -type f -name main.go -print0)
exit $FAIL
```

Remediation guidance (if any FAIL)
- Goal: keep `main.go` as a thin delegator: parse flags, setup logger, construct dependencies, and call an internal runner.
- For each failing command:
  1) Extract CLI parsing into `internal/cli/<command>` (Options + ParseArgs) with tests.
  2) Extract orchestration into `internal/commands/<command>` with a `Runner` exposing `Run(ctx, opts)` and table-driven tests.
  3) Move pure logic and heavy operations into `internal/services/...` or appropriate `internal/adapters/...` packages, each with unit tests.
  4) Keep `cmd/<name>/main.go` to ≤ 30 LOC: parse via CLI package, setup, and invoke the runner; do minimal error logging and exit codes.
- Specific notes:
  - cmd/api: move router/handlers and startup into `internal/api` (server builder) and `internal/commands/api` (runner). Keep `main.go` to: setup logger, build server from config, start.
  - cmd/export-dataset: already has internal runner/services partially. Migrate remaining inline SQL/CSV writing into `internal/services/exportdataset` and `internal/commands/exportdataset` fully.
  - cmd/import-keepers: extract CSV parsing and DB writes into `internal/services/keepers` and a small runner.
  - cmd/precompute-features: extract the workflow into `internal/commands/precompute` and move DB/replay logic into services with small helpers.
  - cmd/weather-worker: move `parseIDs` helper to `internal/cli/weatherworker` or a small `internal/helpers/ids` and rely on CLI/options.
  - cmd/team-select: move the `notImplementedRepo` stub to tests or `internal/adapters/db/teamselectrepo` and delegate to a runner.
